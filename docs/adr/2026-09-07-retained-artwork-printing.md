# ADR: Retained artwork and painted build PDFs

Status: accepted
Date: 2026-09-07

Paint is an optional versioned document on each part or scene object. Commands use a stable owner-local Y-up frame; the original embedded image is retained. One Canvas 2D compositor replays paint and partial erasure chronologically on an isolated surface, then adds the substrate. The physical contour and actual joint holes remain separate. Changing a contour changes clipping, without stretching or deleting retained marks.

The implemented retained command set is brush/pencil, erase, line, and solid rectangle/ellipse. Base color is the substrate. An eraser changes only earlier painted/image pixels; a later mark can repaint that area. Save/Open preserves the document, original embedded asset, stable frame, owner transform, and independent contour so editing can continue without the prior browser. Canvas, texture, and PDF derivatives are disposable. Owner movement/rotation/scaling uses the same transform in each renderer; changing the physical contour does not redefine the artwork frame.

Import object embeds the accepted original PNG, JPEG, WebP, or local SVG bytes in `textureUrl`. Its 512-pixel raster decode is only a transient contour input, never the saved source. The worker checks the resulting captured aggregate through the existing portable byte, image-budget, and round-trip gates before committing it. An import callback belongs to that exact project instance; editing, resetting, or replacing it cancels the result, including changes that retain the project id. SVG intrinsic dimensions use the shared local-image policy without rewriting the original markup.

Change shape accepts one explicit outer contour with finite, nonoverlapping, noncrossing edges and room for the actual attachment rings. Invalid candidates keep the existing contour and show a blocker; no smoothing, union, repair, or dropped piece is implied. Fabrication rechecks explicit user contours, while existing imported/default silhouettes retain their original mapping. Decorative marks never become cut/engrave geometry. Draw object creates one explicitly cuttable scene object; image import retains its original source independently of later marks. Explicit Starter rig creation builds an unpainted baseline, enclosing actual kit hole rings where legacy sample outlines did not. Existing projects and guided lessons are not repaired by this constructor.

`BuildPlanV1` carries stable artwork owner references, appearance revisions, and the same local-to-scene transform as its vector contour. The geometry digest excludes paint, imported raster bytes, and base color. The artwork digest includes those appearance inputs. New cuttable objects have their own part references and cut/placement steps. Unattached objects receive no invented holes or hardware. Printable pieces do not require a mechanism. A project containing only a scene object can use the existing path, preview, Blueprint, and Assembly stages without a character or skeleton. Imported images are explicitly designated as scene decoration until the user chooses Cuttable prop.

The geometry worker continues to omit artwork. Its main-thread client owns the captured project, fingerprint, and cancellation signal until painted output finishes. Restoration verifies the captured fingerprint and geometry digest. It never attaches the current editor's artwork to an older request. A canceled or obsolete raster/PDF completion cannot publish its package.

Generated print imagery uses **300 pixels per inch at the piece's physical size**, replayed from commands and the embedded original. Imported raster detail remains limited by its native source. Pieces are processed sequentially; the shared compositor limits each surface to 4,000,000 pixels and 4096 pixels per edge (at most 32 MB for its two RGBA surfaces). An oversized request fails explicitly instead of reducing print quality. This bound is an allocation guard; classroom device measurements are recorded separately in runtime evidence.

PDF imagery and vector outlines use the same affine owner-local-to-page transform. The PDF clips to the exact outer contour and actual holes, draws artwork first, and places cut/hole strokes and exterior labels above it. Letter piece pages remain at 100%; existing mechanism pages retain their native 12-inch MediaBoxes. Front-side artwork is the supported convention. SVG cutting output excludes paint operations.

## PDF dependency boundary

`simplePdf.ts` supplies an ASCII page/font/content writer with one Helvetica resource. It has no image XObjects, alpha masks, PNG decoder, or resource-aware page copying. Extending it to decode arbitrary original PNGs would introduce an unnecessary binary-format subsystem. Existing mechanism and outline-only page construction stays with that writer.

Use lazy-loaded `pdf-lib` 1.17.1 only behind the painted PDF export boundary. Its [`embedPng`](https://pdf-lib.js.org/docs/api/classes/pdfdocument#embedpng) accepts the compositor's PNG and retains transparency. Its [`copyPages`](https://pdf-lib.js.org/docs/api/classes/pdfdocument#copypages) copies the complete resource tree into the build packet. Concatenating page content strings would lose image/font resources. PDF data URIs use the byte-safe download helper; writing their binary characters through a text Blob would corrupt the file.

The final production Vite build inspected on 2026-09-07 emits the PDF library as a separate lazy chunk: **436,413 bytes minified; 182,792 bytes gzip** (`es-BjKvPwxf.js`). The export orchestration chunk is 7,239 bytes minified / 2,985 bytes gzip. Gzip uses Bun, matching the repository budget gate. The library is requested by Build PDF generation, not painting or ordinary navigation. Later bundle changes must be remeasured; these numbers describe that build rather than a permanent budget.

## Verification boundary

`tests/painted-build-packet.test.ts` checks physical transforms, print resolution, independent appearance invalidation, image XObjects/alpha resources through packet merging, and rejected mismatched or canceled sources. `tests/blueprint-package-worker.test.ts` exercises delayed geometry and raster completion ownership. These structural tests do not substitute for rendering an actual downloaded PDF, inspecting the painted result, or testing a physical printer. Normal UI authoring and file-only continuation are covered by the production-preview painting workflow and Orca evidence.

The initial compressed core exceeded the existing 200,000-byte gate after the new shared contracts entered its static import closure. Canonical pin projection and fabrication validation were extracted at their existing seams with golden-output comparisons and compatibility re-exports. SVG/DXF serialization now loads on the explicit export action. No budget was raised. Final bundle and runtime numbers are recorded in [the verification record](../painting-workflow-verification.md).
